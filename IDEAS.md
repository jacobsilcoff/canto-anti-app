# Feature Ideas & Backlog

## ✅ Shipped

- **Fix: "Build vocab deck" failed outright when no shared Gemini key is configured** — `POST /api/vocab-deck` called `_resolve_gemini` eagerly, which raises 503 ("Shared API key is not configured.") with no key set. But nothing the route does needs AI: it creates a label and cards, with audio generated lazily on first play and romanization from the offline oracle. The key is used *only* for the background embedding. So a fresh self-hosted instance — and CI, which has no key — got a 503 instead of a deck. The `try/except HTTPException` meant to cover this was wrapped around `background_tasks.add_task`, one level below where the raise actually happened. Now the key is resolved best-effort and the embedding is skipped when there isn't one (self-healing — `_backfill_card_embeddings` fills them in later). This was the only red in CI/CD, and it had been failing on `main` since before this branch.

- **Fix: AI lessons re-teaching material the course already covered** — Redundancy turned out to be a *visibility* problem, not a filtering one. `create_lesson` registers only a lesson's top-level concepts, so a GRAMMAR concept's `items` — the words it actually taught, i.e. most of the vocabulary in a grammar-forward course and most of a textbook unit — never became `course_concepts` rows. The planner's prompt couldn't see them and `_filter_new_concepts` couldn't match them, so a later lesson re-taught the same words under a fresh key, unguarded. The planner was also judging repetition from the last **three** lesson summaries, with no list of the course's other lessons at all. `db.get_next_lesson_context` now also returns **`taught_words`** (every word from every lesson's `concepts_json`, grammar `items` included) and a **`lesson_index`** (title + summary of every lesson, textbook ones marked 📕); both are rendered into the planner prompt and `taught_words` feeds the concept filter. Added a third dedup layer, `main._semantic_dup_lesson`, that embeds the *planned lesson's topic* against every existing lesson's `title — summary` — the only check that catches "Ordering at a restaurant" coming back as "At the café", where neither the concept keys nor the words overlap; a hit re-plans once with the clashing lesson named. Textbook units also stopped being created with an empty summary (`main._textbook_unit_summary`), which had made them invisible to the planner's "don't re-cover a completed unit" rule.
- **Diagnostic: `scripts/lesson_overlap.py`** — read-only, no LLM. Compares a course's stored lessons pairwise on taught words, drill answers, concept keys and title tokens, and annotates each flagged pair with *which guard let it through* (plus a count of words invisible to the planner), so lesson redundancy can be measured on a real course instead of argued about. `--list`, `--course N --verbose`, `--json`.

- **Fix: the "What's new" popup reappeared on every page** — Reported on the textbook page, but it happened site-wide: after a release, the update notice replayed on *every* navigation for the whole tab session instead of showing once. Root cause was a cache write-through gap, not the tour itself. `tour.js` reads `/api/settings`, which `app-shell.js` answers from the `/api/bootstrap` snapshot held in **sessionStorage** — a cache that outlives a page load. `markSeen()` correctly POSTed `/api/tour-seen` and the server stored the new version, but nothing updated the cached `settings.tour_seen`, so the next page read the OLD value and showed the same steps again. (An earlier fix moved `markSeen()` from dismiss-time to show-time, which addressed the server side only — the client cache still lied.) `CantoShell.invalidate()` couldn't have fixed it either: its `dirty` set is in-memory and rebuilt on every navigation, so it can't carry a mutation across a page load. Added **`CantoShell.patch(key, partial)`**, which writes through to the sessionStorage snapshot; `tour.js` now patches `settings.tour_seen` when the tour is shown, `/api/tour-seen` also marks the settings section dirty, and a `seenMarked` guard stops the duplicate POST. Verified in a real browser (Playwright): the popup went from 5-of-5 page loads to 1-of-5, with the new-user, returning-user, already-up-to-date and explicit-dismiss paths all still correct.

- **Streaks now run on the learner's clock — five fixes to "I studied every day and lost my streak"** — Root cause: every day boundary in the app flipped at **00:00 UTC for everyone** (an earlier fix made reads and writes *consistently* UTC, not *local*). UTC midnight is 5pm in California and noon in Auckland, so two consecutive local study days could land in the SAME UTC day — a phantom gap that broke a genuinely-kept streak, and an XP ring that reset mid-afternoon. (Reports came from the Americas and Asia-Pacific and never Europe, where the rollover lands at ~1am local, which is why it looked intermittent.) Fixed end to end: **(1) Per-user time zones** — a `timezone` user setting (IANA name), auto-detected by `static/app-shell.js` (`Intl.DateTimeFormat`) and PUT only when it changes; `db` gains `resolve_timezone`/`local_today_str`/`local_day_bounds`/`user_today`, and the streak, daily-XP ring, daily quests and the new-cards-per-day cap all resolve through it (no `date('now')` left in any per-user day comparison). Unknown/absent zone ⇒ UTC, so this is a pure widening; changing zones can't shorten an earned streak (`db.ensure_min_streak`, insert-only). **(2) Freezes evaluate at write time** — the 🛡 shield used to be applied only on a *read*, and only while the last activity was exactly two days old, so if the day's first request was a review (glasses plugin, offline sync, a deep link into a session) today's row hid the gap and the streak reset with the freeze unspent. `db._mark_study_day` now bridges on every study write and looks only at activity *strictly before today*, making the outcome order-independent. **(3) Freezes bridge multi-day gaps** — N shields cover N missed days (all-or-nothing, since a part-filled gap still breaks the streak), and they apply whenever the learner returns rather than only the very next day. They're also no longer spent rescuing a single isolated day (`STREAK_FREEZE_MIN_STREAK`). **(4) Offline reviews count for the day they happened** — queued IndexedDB reviews now carry the local date they were answered and send it as `studied_on`, clamped server-side (`main._clamp_studied_on`: parseable, not future, ≤7 days old); previously an evening session synced next morning lost that day entirely. **(5) `db.get_streak` is pure** — freeze consumption moved to `db.apply_streak_freezes`, so `/api/friends/leaderboard` rendering a friend's streak no longer spends *their* shields and writes activity rows onto *their* account. Adds 25 streak tests (local-day bucketing, the exact four-day collapse from the reports, order-independence, multi-day bridging, backdating, clamping) plus rewritten freeze tests; `tzdata` pinned in requirements so `zoneinfo` resolves on slim images.

- **Drag a unit split straight onto the rendered page** — Splitting a shared page previously meant opening Chapters → Edit divisions and tapping a line out of a text list, which said nothing about where that lands on the printed page. - **Fix: uploaded textbooks that extracted text but rendered no pages at all** — Reported as "it extracts text implying it got the book, then `Couldn't open that PDF for rendering: Failed to load document (PDFium: Data format error)`". Root cause reproduced exactly: **pypdf finds the `%PDF-` header at any byte offset and rebuilds a broken xref by scanning for objects, while pdfium only looks at the start of the file** — so a book with junk in front of its header (CMS exports, mail gateways, some scanners) extracts every page of text and rasterizes *nothing*. New `extract.repair_pdf` tries the cheap byte-preserving fix first (trim to the header — page geometry and the xref stay valid) then re-serializes the parsed document through pypdf (fresh xref + trailer, which also recovers a corrupt one), **verifying each candidate against the rasterizer** before accepting it. It runs at upload (so the stored file is already good) and lazily via `main._ensure_renderable_pdf` when a book is opened or a page is requested, replacing the stored file atomically — so **books already uploaded in this state heal on their next open**, no re-upload. A book that genuinely can't be rasterized now reports `renderable_pages: 0` and reads as extracted text behind one clear banner instead of a per-page error (the client no longer `||`-folds that 0 back into "all pages"). `extract.RendererUnavailable` keeps "no rasterizer on this server" distinct from "this book won't open", so a server gap never rewrites a good PDF or declares its pages unrenderable, and failed repairs are remembered so page requests don't re-attempt a whole-file rewrite. Verified end-to-end in headless Chromium: an 8-page book that previously rendered 0 pages now renders every page.
- **Fix: page cleaning could silently empty a page of real content** — Found while verifying the above. `textbook.strip_repeated_lines` drops running headers/footers by counting lines whose **digit-masked** form recurs on ≥30% of pages, so a book whose pages differ only by a number (numbered drills, a repeated table scaffold) has EVERY line look like boilerplate — and the page was stored as an empty string, silently starving chapter detection, unit planning and lesson authoring of the source they read. A page holding ≥120 chars is now never stripped to nothing: it's kept whole minus bare page numbers, while a genuinely header-only spacer page has too little text to qualify and still cleans out (both directions covered by tests).
- **Fix: mid-page split anchors could trim the wrong line (or nothing)** — Found while making splits visible on real-world PDFs. `textbook._anchor_line_index` took the FIRST line that was a loose prefix of the anchor, so on a book whose extracted text puts short lines first (word-positioned PDFs extract one word per line) a line reading just "Unit" claimed a boundary belonging further down — `split_page` then trimmed the earlier unit to an empty string, and generation silently taught from nothing. The opposite failure existed too: `_source_contains_quote` verifies the AI's anchor against the page as a WHOLE, so it accepts a "line" the page stores across several lines, which the line-by-line trimmer then couldn't find at all — the split verified and did nothing. Matching is now ordered: exact normalized line → a rejoined run of consecutive lines (`_MAX_SPAN_LINES`=12, works with or without spaces so CJK rejoins too) → a prefix of at least 8 chars. `extract._line_matches` (which places the reader's dashed rule) and the client's `_tbAnchorIdx` (text-view marker + split editor preview) mirror the same order, and `locate_page_lines` also matches whitespace-free so a page whose words carry no space glyphs still resolves.
- **See where a mid-page unit split actually lands (reader validation)** — A split is stored as one verbatim line of a shared page, which said nothing about where that is on the printed page, so a split could only be validated by re-reading the raw text. Now `GET /api/textbooks/{id}/splits` returns each boundary as `{page, line, above, below, y}`, where `y` is computed by `extract.locate_page_lines`: it re-extracts the page through pypdf's positioning visitor, rebuilds the lines with their baselines, matches the anchor (whitespace-tolerant), and returns its height as a 0–1 fraction of the crop box — placed in the whitespace above the matched line so the rule never strikes through the heading it marks. The reader fetches this after the first page renders (never blocking the open) and draws a **dashed rule across the page image** with a small ✂︎ chip in the margin, marks the **same boundary in the extracted-text pane** (previous unit's lines dimmed, a labelled dashed divider, the anchor line highlighted) — the text copy being the one generation actually trims, so the two views cross-check each other — and names **both** units in the chapter caption for a shared page. The Chapters TOC now also spells out each cut ("ends on p12 before “Lesson 4”"). Degrades cleanly: an anchor that can't be located (vision-transcribed page, hand-edited anchor) returns `y: null` and is still marked in the text view rather than drawn in the wrong place.

## 51. Boilerplate stripping vs. word-positioned PDFs (needs a real book to judge)
**Complexity: Low | Cost: $0**

`textbook.strip_repeated_lines` treats any line ≤80 chars whose digit-masked form appears on ≥30% of pages as a running header. On a PDF that positions **each word separately** — a shape this pipeline definitely encounters (it's why `_anchor_line_index` needs its span-rejoin fallback) — pypdf extracts roughly one word per line, so ubiquitous function words ("the", "de", "le") each become their own line, recur on most pages, and are stripped from the whole book.

The empty-page floor (`_MIN_PAGE_CHARS_TO_PROTECT`, shipped) stops the catastrophic version of this, but a page that keeps *most* of its words while losing its commonest ones would slip through.

**Not fixed yet on purpose:** the obvious guard (ignore very short lines as header candidates) collides with legitimately short headers — bare page numbers, and CJK running heads like 第三課 that are 3 characters. Picking a threshold blind risks reintroducing header noise for every book to fix a case not yet observed in a real one. Next step is to run a genuinely word-positioned textbook through `clean_pages` and measure what's actually lost before changing the heuristic.

## 43. AI Learning Path (Duolingo-style course) — ⭐ FLAGSHIP
**Complexity: High | Cost: ~$0 (Gemini free tier) | the big bet**

A generative, SRS-aware course that teaches a language from the ground up. **Design decisions locked** (2026-06): CEFR-scaffolded curriculum, unified with the existing SRS deck, lean deterministic MVP first.

**Architecture:**
- **Two-layer generation** — keeps an AI course coherent: (1) *curriculum* skeleton = units + lessons + objectives + target new-concept counts, generated once and regeneratable; (2) *lesson content* = the exercises, generated on demand and **cached** in `lessons.content` (JSON).
- **Concept ledger** — each lesson declares the concepts it teaches (vocab + grammar points). Next-lesson generation is fed a compact *digest* (concept IDs + mastery + weak items to recycle), never raw lesson text → scales without context bloat. The app owns concept IDs; the AI references the provided list and proposes canonical keys for new ones (app dedupes).
- **CEFR scaffold** — a per-level, language-agnostic can-do/topic checklist (A1: greetings, numbers, family, ordering food…) guides the curriculum generator. Reliable + generalizable since CEFR is language-independent. Store as a `learning.CEFR_SYLLABUS` constant (like `LANG_INFO`).
- **SRS fusion** (the differentiator) — lesson vocab becomes **tagged cards** in the existing deck (reuse `create_card` + a course/unit label, like reader story-labels). Generator checks `get_word_statuses` to skip already-known words and recycle weak ones into review exercises. Path ↔ flashcards reinforce each other; this is the "aware of what the user has learned" edge.
- **Exercise-type registry** — each type = JSON schema (what the AI emits) + frontend renderer (widget) + grader. Adding a type later touches only those three. **MVP types are all auto-gradable**: vocab multiple-choice, word-bank sentence build (Duolingo-style tiles), listening (edge-tts audio), cloze/fill-blank, match-pairs. AI-graded free production (translation, comprehension) is **deferred** — costs a call per answer.
- **Foundations module (script + sound system) — ✅ SHIPPED for Hangul + abugida (see Shipped section); wired in skippable (not a hard gate).** Remaining: tonal (Chinese) track, SRS sound-cards. The writing/sound system is a different kind of learning (perceptual/production skill, not meaning), finite & factual, shared per-language. **Key architectural decisions:**
  - **Reuses the segmented-lesson player** — a Foundations lesson is the same `{segments:[{teach,exercises}]}` shape: orientation = a teach segment with no exercises; a grapheme unit = teach (letters+audio) → drills. No new player.
  - **Generalizable = data + per-script-type engines** (must be droppable-in for languages not yet supported). (1) A declarative `FOUNDATIONS` registry per language: `script_type` (alphabetic/abugida/tonal/logographic/latin) + ordered units of type `info` (non-testable orientation, e.g. "Korean letters stack into syllable blocks", "French is a Romance language"), `graphemes` (`{symbol, roman, audio, example}`), `tones` (`{name, number, example_char}`), `words` (curated or AI-proposed-then-validated). Adding a language = fill in data, no code. (2) Per-script-*type* engines (the only script-specific code, shared by all langs of that type): a **decomposer** (`word→[graphemes]`: Hangul jamo math, Devanagari akshara split) powering "words from known letters", plus Foundations exercise builders.
  - **New concept kind `sound`/`grapheme`** → when added to SRS, a **sound-card** (symbol↔sound faces, NO meaning face) via a `card_type` flag (the one schema touchpoint into Phase 3).
  - **New exercise types:** grapheme↔sound, **tone discrimination** ("ma" → which of the 4 Mandarin tones?), consonant+matra **blend** (abugida), **syllable-block assembly** (Hangul). All deterministic from curated graphemes.
  - **"Words from known letters":** curate a grapheme order so useful words unlock early; AI proposes frequent words; we **filter by decomposition** to those using only known graphemes (generic via the decomposer). Logographic (Chinese) has no alphabet → its Foundations = orientation + tones + romanization literacy instead.
  - **Per-script-family shape differs:** Latin = orientation + optional pronunciation primer (no gate); Hangul = letters→blocks→words (gate); abugida = vowels→consonants→matras→conjuncts→words (gate); Chinese = orientation + jyutping/pinyin literacy + tones.
  - **Integration:** Foundations units sit at the FRONT of the `/learn` path, gating vocab for non-Latin scripts. The CEFR vocab syllabus already excludes script/sound.
  - **✓ Korean/Hangul MVP BUILT (on staging):** `foundations.py` = jamo engine (compose/decompose with compound splitting) + curated Hangul track (orientation → vowels → blocks → consonants → words, ordered so 안녕/네 unlock early) + `build_units()` producing pre-built lesson `content` (segments). Reuses choice/listening/match; new `block_build` type (assemble consonant+vowel into a syllable, live-composed in JS via the Unicode formula). Words validated by `decompose_hangul ⊆ taught`. Romanisation from korean-romanizer; letters voiced via a representative syllable (가 for ㄱ). Wired into course creation (`foundations.build_units` prepended in `/api/courses`), `db._insert_units` persists pre-built content, info-only lessons supported by the player. **Grammar drilling (constructions + forms), STARTED:** flashcards can't teach grammar because it's generative/paradigmatic/contextual. Design: two mechanisms — (A) **constructions** = sentence frames with typed slots filled procedurally from the learner's KNOWN vocab (SRS-aware → endless fresh practice; slots that are verbs call the conjugation engine); (B) **form/paradigm drills** = produce the right conjugation/declension, distractors are other cells of the same paradigm; plus (C) **contrast** drills (ser/estar…) reusing `choice` + the 💡 tips. Key principle (same as romanisation/Foundations): grammar forms are systematic → **compute/curate, don't trust the AI**. `grammar.py` (DONE): French present-tense engine = regular -er/-ir/-re rules (incl. -ger/-cer spelling) + a curated irregular table, **verified 100% against verbecc/Verbiste** which is used only as a dev-time oracle (NOT shipped — it pulls ~90 MB scikit-learn + retrains on load). `build_conjugation_exercises()` makes `form_drill` exercises (reusing `choice`). Wired into `generate_lesson`: French verb concepts (gloss "to …") auto-get conjugation drills.

**Grammar-first lessons + critic pass, DONE:** big reframe (per the "emphasise grammar/sentence construction, vocab is trivial" goal). A grammar concept now produces a dedicated **grammar-first segment**: an explicit English **rule** + **minimal pairs** (two sentences differing in ONE feature) on the teach screen, then **cloze** + **reorder** drills — kept entirely OUT of the vocab pipeline (no ambiguous "say X"). Content comes from a **generator + critic** pipeline (`grammar_lessons.py`): a generator LLM writes rule/pairs/cloze/reorder; a *critic* LLM independently re-derives and judges each item; **rejected items are dropped** (thinner-but-correct). Conceded the "only drill computable forms" rule once generation moved offline — BUT kept the carve-out where a free non-LLM oracle exists: romanization is always recomputed (never trusted from the model) and French present-tense cloze answers/options come from `grammar.py`. Verified artifacts are cached **shared across users** in `concept_content (lang, concept_key)` (expensive once, cheap replay); `main._ensure_grammar_content` generates on cache-miss. Exercises reuse `choice` (cloze + minimal-pair recognition) and `word_bank` (reorder) — no new renderers. Migration 006 adds the table + re-clears cached lessons.

**Rich-block teach content + coherence, DONE:** reframed on **liberal in what you SHOW, strict in what you GRADE**. The teach/explanation content is now authored FREELY by the LLM as an ordered list of typed **blocks** (prose / arbitrary table / examples / contrast / note) — a grammar-textbook page that generalises across languages (the model makes whatever paradigm tables/explanations the language needs), rendered by us (no raw HTML, no hardcoded French-shaped tables; audio + romanization survive). The critic verifies each block and drops rejected ones. INTERACTIONS stay constrained with strict verified answer keys (engine-checked French cloze, recomputed romanization). Also: **curriculum coherence** — `_build_curriculum_prompt` now forces every lesson to be a single coherent chapter (title/objective/concepts match; LLM picks the axis — communicative topic OR grammar point), fixing the "être conjugation under Hello & Goodbye" discord caused by the earlier grammar-backbone over-correction. Player layout switched to natural height + a reserved feedback slot (fixes the full-viewport-gap "weird resizing"). Migrations 008–010 cleared the now-stale cache. NOTE: existing courses keep their old (incoherent) curriculum until **regenerated** — only lesson *content* auto-refreshes.

**Reference tables on the teach screen (SUPERSEDED by rich blocks):** grammar explanations can now show a table (generic `{title, columns, rows}` shape, rendered as an HTML table with script-font cells). A verb concept's **conjugation paradigm** is **engine-computed** (`grammar.conjugation_table`) — never the LLM; the generator is told NOT to produce conjugation tables. The generator MAY emit *other* paradigm tables (article/pronoun/ending grids), critic-verified cell-by-cell and dropped if any cell is wrong. **Reflexive-verb fix (DONE alongside):** `grammar.conjugate_present` refuses reflexive/pronominal verbs (was silently producing wrong "s'appelent"); the conjugation override only fires when the model's cloze answer is a real paradigm cell; a `_cloze_is_sane` guard drops clozes whose filled sentence duplicates the answer word.

TODO (deferred): **constructions / controlled-vocab enrichment** (fill drill slots from the learner's KNOWN SRS deck via *typed* slots — noun swaps change agreement, so slots carry gender/number/classifier) — the user's main excitement; a grammar-**DAG** syllabus (LLM-named concepts + cross-lingual tags + L1-contrast weight, generated once per language, replacing vocab-themed units); concept mastery → sequencing via the existing SRS; error-correction drills; German article/case tables; more tenses & languages.

Materialisation asks the AI for distinct targets + a one-sentence usage `note` per confusable/grammar item; that note is attached to each exercise as a `tip` and shown as a 💡 after answering (the "AI info on trap questions" idea).

**Reliability rework (critical fix), DONE:** the original Phase 2 let the AI generate target text AND answer keys for exercises — which violated the "content from translate()+romanizers, never the AI" principle and produced wrong answers/characters/directions (esp. Cantonese: "comment"="what", 呢好 `ne1 hou2`, "si1"→"four"). The AI now only translates + writes the teach intro/notes. `word_bank` dropped from generation (needs validated sentences — deferred). Per-lesson "↻ regenerate" button to refresh stale/old lessons.

**Cost notes:** One Gemini call per session batch (~500 output tokens). At 10 users × 4 sessions/week = 160 calls/month × 500 tokens = 80K tokens = $0.024/month on paid tier. Free tier handles it.

**Open questions:**
- Does a sentence comprehension rating update SM-2 scores for all constituent word cards?
- Should sentences be cached between sessions or always freshly generated?
